# Feature: Multi-Language Support ("Vibe Switcher")

> Project-local reference for the i18n system. Read this to understand or extend
> translations without re-deriving the design. Committed with the code, so it
> survives context resets and branch switches.

- **Status:** shipped on branch `chore/project-setup-update` — commit `3816f5b`
  `feat(i18n): add multi-language Vibe Switcher (6 locales)`
- **Approved plan:** `~/.claude/plans/i-want-to-setup-replicated-feather.md`
- **Library:** [`next-intl`](https://next-intl.dev) v4, "without i18n routing" mode

## What it does

Lets a reader choose the language/tone FocusPond speaks in. Presented on the
landing page as the on-brand **"Vibe Switcher."** Six locales (BCP-47 codes,
which double as `<html lang>` and the message-folder names):

| Code  | Language        | Notes                                                   |
| ----- | --------------- | ------------------------------------------------------- |
| `en`  | English         | **Default + source of truth.** The "calm" vibe.         |
| `pcm` | Nigerian Pidgin | The "relaxed" vibe. Fully drafted.                      |
| `fr`  | French          | Fully drafted.                                          |
| `ig`  | Igbo            | Chrome + headings drafted; prose falls back to English. |
| `yo`  | Yorùbá          | Chrome + headings drafted; prose falls back to English. |
| `ha`  | Hausa           | Chrome + headings drafted; prose falls back to English. |

## How it works (data flow)

1. The reader picks a locale in the **Vibe Switcher** → writes the `NEXT_LOCALE`
   cookie (`src/features/i18n/lib/locale-cookie.ts`) → `router.refresh()`.
2. On every request, `src/i18n/request.ts` reads that cookie **server-side**,
   loads the locale's namespace JSON, and **deep-merges it onto English** so any
   missing key falls back to English. No flash of English, no per-language URLs.
3. `src/app/layout.tsx` sets `<html lang={locale}>` and wraps the tree in
   `NextIntlClientProvider`. Components read copy with `useTranslations(...)`
   (works in both server and client components).

## Key files

| Path                                                | Role                                                                                                  |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `src/i18n/config.ts`                                | Locale list, `SUPPORTED_LANGUAGES` (drives the switcher), `namespaces`, `LOCALE_COOKIE`, `isLocale()` |
| `src/i18n/request.ts`                               | Cookie → messages loader with deep-merge English fallback                                             |
| `src/i18n/messages/{locale}/{namespace}.json`       | The translations. Namespaces: `common`, `nav`, `marketing`, `mood`                                    |
| `src/i18n/messages/_status.json`                    | Review state per locale/namespace (draft vs. reviewed, coverage)                                      |
| `src/i18n/messages.test.ts`                         | Guards that no locale has keys missing from English (catches typos/stale keys)                        |
| `src/global.ts`                                     | next-intl TS augmentation → typed `t()` keys (no codegen)                                             |
| `src/features/i18n/components/LanguageSwitcher.tsx` | The Vibe Switcher dropdown                                                                            |
| `src/features/i18n/lib/locale-cookie.ts`            | Writes the locale cookie client-side                                                                  |
| `next.config.ts`                                    | Wrapped with `createNextIntlPlugin("./src/i18n/request.ts")`                                          |

Switcher is placed in the landing `NavBar` + `Footer` and the app `TopBar`.

## How to extend

- **Add/change copy:** edit `en/<namespace>.json` **first** (source of truth),
  then translate in the other locales (or leave it to fall back to English).
- **Add a namespace:** add its name to `namespaces` in `config.ts` **and** to the
  `Messages` type in `global.ts`, then create `en/<name>.json`.
- **Data-driven lists** (features, benefits, FAQs, moods, tabs…): the data files
  keep only structure (icons, images, hrefs) + a stable literal `key`. Add the
  key to a literal-union type in `src/types/landing-page/index.ts` (or `MoodId`
  in `moods.ts`) so `t(`items.${key}.title`)` stays type-checked.
- **Add a locale:** add its code to `locales` + an entry in `SUPPORTED_LANGUAGES`
  in `config.ts`, then create `src/i18n/messages/<code>/`. Verify the fonts
  (Manrope/Sora) render its diacritics.

## Gotchas / decisions

- The dynamic import in `request.ts` uses a **relative** path (`./messages/...`),
  **not** the `@/` alias — otherwise the bundler can't build the require-context.
- **Cookie, not URL routing:** simpler, fits the "personal vibe" framing and the
  PWA, no `app/[locale]/` restructure. Trade-off: no per-language SEO (can be
  added later via next-intl's routing mode — see the plan's "out of scope").
- **English fallback is intentional** for the partial `ig/yo/ha` prose. The drafts
  are LLM-generated and flagged in `_status.json` for fluent review.

## Not yet covered (follow-ups)

- **`contact`, `waitlist`, `pricing` pages** still have hardcoded English strings
  — not yet extracted into message catalogs.
- **Fluent review** of `ig/yo/ha` (and ideally `pcm`/`fr`) drafts; update
  `_status.json` `reviewed: true` as each is checked.
- **Diacritic font audit:** confirm the local Manrope/Sora subsets fully cover
  Yorùbá/Igbo combining marks (renders correctly in testing, but not audited).
- **Community "suggest a better translation"** flow (nice-to-have).
